# Edge-Case Matrix (R4, R5, R8, R9, R11)

Report-only. Seeded from `sweep-catalog.md` §3 (the numbered ride-share edge-case
catalog) and `greenfield-extensions.md` §4 (the TRIGGER→DETECTION→SYSTEM
STATE→USER EXPERIENCE→BUSINESS RULE→RECOVERY→ESCALATION→AUDIT RECORD→TEST chain,
plus the three distributed-step questions: can it run twice, what if the network
fails after a write succeeds, and how are duplicate/out-of-order events
compensated). Covers the 7 flows the task specifies — rider booking, dispatch/
offer, in-trip, payment settlement, cancellation, SOS, driver go-online — against
9 edge-case categories each: network loss, app kill, duplicate tap, clock skew,
concurrent actors, provider outage, stale token, low battery/background, partial
failure between two writes.

## Method

Most rows are **not** newly derived — they are pulled directly from scenario-card
tables the domain lanes already built for this exact purpose (`dispatch.md` §5/5b/5c,
`money-cra.md` §4, `driver-journey.md` §3, `rider-journey.md` (b), `trust-safety-fraud.md`
(a)/(b)/(c), `corporate.md` §6, `reliability.md` §9), all of which independently used
the same sweep-catalog numbering and the same chain. This file's job is to organize
that evidence by **flow** (as the task asks) rather than by lane, cross-reference the
9 edge-case categories the task names against the ~48 sweep-catalog scenarios, and
flag every category × flow combination no lane actually covered as `Unknown — not
checked` rather than silently omitting it. Citations point to the lane report and
scenario number (e.g. "dispatch.md #5") so the underlying grep/`path:line` evidence
can be traced back; this file does not re-paste every cited line.

**Verdict key:** GREEN = handled, with real evidence (code + usually a test).
YELLOW = partial — a real mechanism exists but has a caveat, an unclosed race
window, or an untraced sub-case. RED = confirmed unhandled, or handled in a way
that fails unsafely (silent, no escalation). `Unknown` cells are marked as such,
not guessed.

**Evidence labels:** each row's verdict is INFERRED-from-lane-citation unless
marked VERIFIED (this pass re-read the cited code directly) or UNKNOWN.

## Cross-flow observations

- **The same unshipped fix (`DISPATCH-003` / `driver_availability_v2_enabled`) is the
  root cause of the weakest "partial failure between two writes" cell in *two*
  different flows** (dispatch/offer and driver go-online) — a single flag flip
  would close both at once, making it one of the highest-leverage fixes surfaced by
  this matrix.
- **TSF-001 (SOS on-call paging) is the single reddest cell in the whole matrix**: a
  runbook that on-call staff would actually follow during a live emergency describes
  infrastructure that isn't wired to anything. Every other SOS-flow cell is GREEN or
  well-mitigated by comparison, which makes this one starker, not less important.
- **Two independent lanes reaching the same "not traced" conclusion** (in-trip
  duplicate-tap/forgot-to-end-trip, and driver-ends-trip-early distance validation)
  is treated in this matrix as stronger evidence of a real gap than a single lane's
  untraced item, per the task's instruction to search with several spellings before
  claiming an absence — here the "search" is two separately-run lanes converging.
- **The three distributed-step questions, answered where a lane addressed them
  explicitly:** "can it run twice?" is answered GREEN for the CAS-guarded ride
  actions (accept/cancel/no-show) and the idempotency-keyed booking/refund/tip
  paths, but explicitly **not yet answered** for the corporate wind-down debit
  (CORP-001, confirmed it *can* run twice, badly) and the go-online availability
  flip (DISPATCH-003, same root cause in two flows above). "What if the network
  fails after a write succeeds?" is GREEN for the card-charge/DB-write race
  (money-cra.md #28) and RED/Unknown for the late-tip and corporate-close cases.
  "Duplicate/out-of-order events?" is the one Stripe-webhook ordering explicitly
  fails on (money-cra.md #29's `dispute.updated`-after-`closed` overwrite).
