Variant A Rationale

Map fills all 812px at all times. Glass cards float over it. Driver always has spatial awareness — sees intersections, landmarks, and traffic while reading status info.

Key Decisions

• Earnings chip always top-left — motivation visible at a glance
• Online toggle always top-right — deliberate to avoid accidental tap
• SOS on every active state (navigating/arrived/inprogress)
• Offer panel auto-expires 15s — countdown shown in topbar
• Fare breakdown on completion — transparency = driver trust

State Design

Offline Motivational + earnings potential
Online Minimal — map + pulse animation
Offer Full attention takeover
Navigating Route + rider compact card
Arrived OTP verification prominent
In Trip Fare meter + route
Completed Earnings celebration

What to Evaluate

Does the floating glass still feel readable against a busy map?
Is the offer feel urgent without being stressful?
Does the earnings amount motivate?

Map takes the top 45% of screen, dedicated UI panel below. Clear visual separation — text is always legible regardless of map content. Less map coverage but more stable action area. Lyft-style approach.

Variant B Rationale

Dedicated panel zone below the map fold. Text and buttons never compete with map content. Easier to add information without readability concern.

Trade-offs vs A

+ Better text legibility always
+ More stable button area
+ Easier for eyes to find controls
− Less map visible (45% vs 100%)
− Map feels disconnected from panel
− Feels more "form-like"

Best for

Drivers who prioritise reading info quickly over map awareness. Daytime use with bright ambient light where glass overlays would be hard to read.

Variant C — Status-First ★ Recommended

Layout adapts per state. Offline = motivational full-screen. Offer = full-attention takeover. Navigation = map-dominant with minimal card. Completed = earnings celebration. Each state gets its optimal layout — not a compromise.

Why Status-First?

A driver's world changes radically between states. Offline = motivation. Offer = urgent decision. Navigation = eyes on road. Forcing one layout to serve all these contexts always creates compromise.

State → Layout Logic

Offline Full-screen motivation + weekly stats
Online Map fills screen + minimal float pill
Offer Map thumbnail + full info + big CTA
Navigating Map 100% + compact glass card
Arrived Map + OTP focus
In Trip Map 100% + compact meter
Completed Full-screen earnings moment

Cognitive load design

Each state asks the driver to do exactly ONE thing. No competing CTAs. The primary action button is always the same height, same corner, same color pattern — muscle memory builds over time.

Recommendation

Variant C gives each state its best possible layout. More implementation work but significantly better UX. Recommend C for production, A as simpler fallback.
