TASK 17 — OBSERVABILITY
================================================================================

[17-1] HIGH | Sentry send_default_pii=True without scrubbing filter
File: backend/server.py:179
Finding: Sentry is initialized with send_default_pii=True. No before_send filter
exists to strip request/response bodies containing phone, address, or payment
data before events are sent to Sentry's US cloud. PIPEDA cross-border data
transfer exposure.
Fix: Add before_send callback in server.py:173 that redacts phone, card_last4,
addresses, and email fields from request/response bodies and user context.
Effort: 2 h
Risk score: 32 (HIGH × org × possible)
Regulations: PIPEDA
Owner: backend + infra · Sprint: P1

[17-2] MEDIUM | SOS trigger catch block does not log failure to crash reporter
File: rider-app/store/rideStore.ts:501-517
Finding: triggerEmergency shows an Alert but does not call recordNonFatal or
emit any structured event. Per the D17 kickoff rider-specific risk, SOS trigger
failure must always reach the crash reporter even when the network fails.
Fix: Add recordNonFatal(error, {action: 'SOS', rideId}) in the catch block.
Effort: 0.5 h
Risk score: 8 (MEDIUM × self × possible)
Regulations: PIPEDA
Owner: rider-app · Sprint: P1

[17-3] HIGH | Backend logs not structured JSON; HTTP requests never logged
with request_id / user_id / latency
File: backend/server.py:138-143
Finding: Loguru is configured with a text-only format string. No middleware
emits a per-request log line with request_id, user_id_hash, route, status,
duration_ms. SLIs (latency, error rate) cannot be extracted from current logs.
Fix: Replace loguru formatter with JSON encoder; add request/response logging
middleware. Hash user_id before output. Effort: 4 h
Risk score: 32 (HIGH × org × possible)
Regulations: PIPEDA, SOC2
Owner: backend + infra · Sprint: P1

[17-4] MEDIUM | /health endpoint only checks Supabase; Redis unchecked
File: backend/routes/main.py:32-52
Finding: /health runs db_supabase.ping() only. Redis (rate-limit, WS pub/sub,
session) is not health-checked. A Redis outage degrades the service silently
while /health still returns 200 — exactly the failure mode DV-6 flagged.
Fix: Add Redis pings to RATE_LIMIT_REDIS_URL and WS_REDIS_URL; return 503 on
failure. Effort: 1.5 h
Risk score: 16 (MEDIUM × org × possible)
Regulations: SOC2
Owner: backend + infra · Sprint: P1

[17-5] MEDIUM | Background loops emit startup logs but no per-cycle heartbeat
File: backend/core/lifespan.py:76-152
Finding: 7 background loops (surge, scheduled dispatch, payment retry, document
expiry, corporate auto-topup, low-balance nudge, allowance reset) log at spawn
but not after each cycle. Per D17 checklist, each loop must emit a heartbeat so
silent failures alert SRE.
Fix: Inside each loop body, emit logger.info("heartbeat", extra={loop_name,
cycle_at}) after the work cycle. Add monitor that alerts if heartbeat gap >
2× interval. Effort: 3 h
Risk score: 16 (MEDIUM × org × possible)
Regulations: SOC2
Owner: backend + infra · Sprint: P1

[17-6] LOW | Crash reports lack ride_id context during active rides
File: rider-app/app/_layout.tsx:184,267
Finding: setUser(uid) is called at cold start but ride_id is not added as
breadcrumb or attribute when a ride is in progress. Crashes during active rides
cannot be correlated with ride state without cross-referencing timestamps.
Fix: After setUser(uid), if currentRide exists, call addBreadcrumb(ride_id) or
set it as a custom crash attribute. Effort: 1 h
Risk score: 2 (LOW × self × rare)
Regulations: PIPEDA
Owner: rider-app · Sprint: P3

[17-7] RECOMMENDATION | No audit_logger.py file; ride lifecycle events not
routed through a structured audit table
File: backend/ (no audit_logger.py found)
Finding: The D17 checklist expects a backend/utils/audit_logger.py emitting
rows to an `audit_events` table for: ride requested/completed, payment charged,
wallet topped up, SOS. This file does not exist. Financial-reconciliation (D20)
and dispute-resolution depend on this audit trail.
Fix: Create backend/utils/audit_logger.py with emit(event_type, user_id_hash,
ride_id, metadata) inserting into audit_events table. Wire into state
transitions. Effort: 5 h
Risk score: 2 (RECOMMENDATION × org × rare; will escalate on D20 audit)
Regulations: PIPEDA, PCI-DSS
Owner: backend · Sprint: P2
Confidence: low (requires probe: confirm no file exists under an alternate name)

[17-8] MEDIUM | WebSocket onerror logs via console.log, not crash reporter
File: rider-app/hooks/useRiderSocket.ts:190-192
Finding: ws.onerror handler calls console.log; errors never reach Crashlytics.
Patterns of WS errors affecting specific users/regions are invisible to ops.
Fix: Replace console.log with recordNonFatal(error, {context: 'ws-rider',
state: connectionState}). Effort: 1 h
Risk score: 8 (MEDIUM × self × possible)
Regulations: SOC2
Owner: rider-app · Sprint: P2

[17-9] HIGH | No Sentry before_send filter — exception payloads may include
raw phone / card / address
File: backend/server.py:173-180
Finding: Exceptions on payment/wallet/ride paths trigger Sentry events. With
no before_send filter, request URLs, headers, and bodies are forwarded to
Sentry unchanged. Compounds finding 17-1.
Fix: Implement before_send that redacts URL query params, Authorization
header, and body fields matching PII regex. Effort: 3 h
Risk score: 32 (HIGH × org × possible)
Regulations: PIPEDA, PCI-DSS
Owner: backend + infra · Sprint: P1

[17-10] PASS | Request-ID middleware implemented and propagated
File: backend/core/middleware.py:110-119
Evidence: RequestIDMiddleware generates X-Request-ID, binds via
logger.contextualize(), echoes in response headers. Enables end-to-end tracing.

[17-11] PASS | Firebase Crashlytics integrated and initialized at cold start
File: rider-app/app/_layout.tsx:182
Evidence: initFirebaseServices() called on cold start. rideStore + walletStore
call recordNonFatal on error paths.

[17-12] PASS | PrivacyInfo.xcprivacy declares all tracked API reasons
File: rider-app/app.config.ts:42-72
Evidence: NSPrivacyAccessedAPITypes + NSPrivacyCollectedDataTypes list precise
location, phone, email, payment info, crash data, performance data — linked
not tracking. Satisfies Apple's App Privacy requirement.

[18-1] HIGH | Wallet balance not refreshed on app foreground; stale balance cached
File: rider-app/store/walletStore.ts:73-81
Finding: fetchWallet() exists but is never invoked on
AppState.addEventListener('change', 'active'). Rider backgrounds the app,
returns with cached balance; a payment attempt may fail with a confusing
"insufficient funds" while the UI still shows the old higher balance.
Fix: Add useWalletRefresh hook in rider-app that listens to AppState
transitions and calls useWalletStore.getState().fetchWallet() on 'active'.
Wire alongside useRiderSocket in _layout.tsx. Effort: 1.5 h
Risk score: 16 (HIGH × self × possible)
Regulations: PIPEDA
Owner: rider-app · Sprint: P1

[18-2] MEDIUM | Payment idempotency not enforced on app-side retry
File: rider-app/store/rideStore.ts:477; backend/routes/rides.py:1315-1332
Finding: POST /rides/{id}/complete from completeRide() does not pass an
Idempotency-Key header on retry. Backend relies solely on Stripe's
ride-charge-{ride_id} key (24h dedup). A retry >24h after an aborted first
attempt (network drop while charge succeeded) could double-charge.
Fix: Generate idempotencyKey = uuid4() in completeRide() before POST; pass
as header. Backend stores/checks in payment_idempotency_map table (30d
retention) before initiating Stripe call. Effort: 3 h
Risk score: 16 (MEDIUM × org × possible)
Regulations: PCI-DSS
Owner: rider-app + backend · Sprint: P1

[18-3] RECOMMENDATION | Redis replica/sentinel not deployed; single-AZ risk
File: docs/runbooks/redis-down.md:57,99
Finding: Runbook notes "No Redis replica configured (single-AZ risk)" and
"Long-term: add Redis Sentinel / Cluster failover". For multi-replica
backend, Redis pub/sub failure forces scaling to 1 replica to restore
correctness — losing HA during an outage.
Fix: Deploy Redis Sentinel or Cluster; update runbook with failover
procedure; test quarterly. Effort: 8 h
Risk score: 4 (RECOMMENDATION × org × rare) — mitigated_by:
docs/runbooks/redis-down.md
Regulations: SOC2, SK-TNC
Owner: infra + devops · Sprint: P2

[18-4] PASS | WebSocket reconnect: exponential backoff w/ jitter, cap 30s
