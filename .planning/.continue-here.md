### 1. Admin login BFF bug (40f4ad42) — CRITICAL
**Root cause:** The super-admin login path in `backend/routes/admin/auth.py` was calling
`CookieManager.set_auth_cookie()` on the FastAPI response (port 8000). Since admin login
goes through the Next.js BFF proxy (`/api/admin/auth/login/route.ts` on port 3000),
FastAPI cookies are silently discarded — the browser only sees the Next.js response.
The Next.js proxy already correctly handles HttpOnly cookie storage for the refresh token.
Fix: removed CookieManager calls, added `token` + `refresh_token` to the return dict,
consistent with the staff member path.

**Verified:** Playwright confirmed login redirects to `/dashboard` with live data.

## Key architectural knowledge

- **Admin BFF pattern:** Browser → Next.js `/api/admin/auth/*` → FastAPI backend.
  Cookies must be set on the Next.js response (port 3000), never on FastAPI response (port 8000).
  The Next.js login route strips `refresh_token` from JSON body and stores it in HttpOnly cookie.

- **Rate limiter uses in-memory storage** (no Redis in dev). State clears on backend restart.
  In-memory lockout is why restarting the backend unblocks a locked account.

- **Kotlin source of truth:** `node_modules/@react-native/gradle-plugin/gradle/libs.versions.toml`
  → kotlin="2.1.20", agp="8.12.0". Both `app.config.ts` files must match.

- **Admin .env.local** is gitignored. Contains `NEXT_PUBLIC_API_URL=http://localhost:8000`.
  This file must exist locally — not in the PR.
