### #2355 — App location pricing bugs (rider-app)

Riders/drivers could be dispatched to the wrong physical location.
- **Files/lines:** `rider-app/store/rideStore.ts` (`addRecentSearch`/`loadRecentSearches`, new `RECENT_SEARCHES_KEY='recent_searches_v2'`, TTL, validity check, ~L1015-1060); `app/search-destination.tsx` (`handlePredictionSelect` ~L191-210, `handleTextChange` ~L237-260); `app/confirm-pickup.tsx` (~L69-131), `app/pick-on-map.tsx` (~L59-115).
- **Before/after (rideStore.ts):**
  ```ts

  AsyncStorage.setItem('recent_searches', JSON.stringify([location, ...filtered].slice(0,10)));
  // after
  const key = normalizeAddressKey(location.address);
  const filtered = recentSearches.filter(s => normalizeAddressKey(s.address) !== key);
  const updated = [{ ...location, saved_at: Date.now() }, ...filtered].slice(0, 10);
  ```

- **Avoidable?** Yes — unvalidated/never-expiring client cache design was the root gap; a TTL/validity check should have existed from day one.

### #2346 — Stripe SDK v15 serialization fix
- **Issue/gap:** Production 503 on `POST /api/admin/stripe/import/validate`. Stripe SDK v15 renamed `to_dict_recursive()` to private `_to_dict_recursive()`; the old `AttributeError`-fallback to `dict(obj)` itself raised `KeyError: 0` under v15.
- **Files/lines:** `backend/services/stripe_mapping_import_service.py::_retrieve_stripe()` (~L479-488); `backend/services/stripe_kyc_sync.py::refresh_driver_kyc()` (~L173-183).
- **Before/after:**
  ```python
  # before
  try:
      return obj.to_dict_recursive(), None
  except AttributeError:
      return dict(obj), None
  # after
  fn = getattr(obj, "_to_dict_recursive", None) or getattr(obj, "to_dict_recursive", None)
  if callable(fn):
      try: return fn(), None
      except Exception: pass
  return dict(obj), None
  ```
- **Benefit:** Restores the Stripe mapping-import validate/commit endpoints and KYC refresh — matches the pattern already proven in `webhooks.py:431`.
