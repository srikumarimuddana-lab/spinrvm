[17-1] HIGH | WS disconnect logs missing last-heartbeat timestamp + close code
File: backend/routes/websocket.py:439,544
Finding: WebSocket error handler logs a generic message without the close_code
or last-heartbeat timestamp. Dispatch-debugging requires both.
Fix: Emit structured disconnect event {connection_key, client_type,
last_heartbeat_ts, close_code}. Effort: 1.5 h
Risk score: 16 (HIGH × self × likely)
Regulations: PIPEDA
Owner: backend · Sprint: P1

[17-2] MEDIUM | Background location subscription has no error callback on
permission revocation
File: driver-app/hooks/useDriverDashboard.ts:320-377
Finding: Location.watchPositionAsync has no error handler. Backend is never
notified when the OS kills the background task or the driver revokes
permission — dispatch continues with stale GPS.
Fix: Add error callback emitting captureException + POST
/drivers/location-telemetry with stop reason. Effort: 2 h
Risk score: 12 (MEDIUM × org × possible)
Regulations: PIPEDA
Owner: driver-app · Sprint: P1

[17-3] MEDIUM | Crash reports omit driver_id and ride_id in extras
File: driver-app/store/driverStore.ts:408,507,521
Finding: recordNonFatal calls pass {store, action} only. Support triage is
ambiguous: cannot determine which ride or driver was affected.
Fix: Augment recordNonFatal with {driver_id, ride_id} from activeRide context.
Effort: 1 h
Risk score: 8 (MEDIUM × self × likely)
Regulations: PIPEDA
Owner: driver-app · Sprint: P2

[17-4] MEDIUM | Stripe API failures logged as .warning() instead of .error()
File: backend/routes/payments.py:169,191,256
Finding: Stripe API errors use logger.warning(), violating the CLAUDE.md rule
that critical-path DB/auth/payment errors must use .error(). Production log
aggregation typically drops warnings — Stripe failures silently missed.
Fix: Replace logger.warning with logger.error; include full exception.
Effort: 0.5 h
Risk score: 8 (MEDIUM × org × possible)
Regulations: PCI-DSS, SOC2
Owner: backend · Sprint: P1

[17-5] MEDIUM | document_expiry_loop has no success-path heartbeat
File: backend/utils/document_expiry.py:192-200
Finding: Loop logs only on exception, not on each successful iteration. 12 h
interval means a stuck loop can go 24+ h before detection. Related to DV-2
(doc-expiry wrapper bug) — if that fix lands but the loop silently stops,
nobody notices.
Fix: Emit logger.info("document_expiry_heartbeat",
extra={last_run_at, drivers_checked, drivers_suspended}) after each cycle.
Effort: 0.5 h
Risk score: 8 (MEDIUM × org × likely)
Regulations: SOC2
Owner: backend · Sprint: P2

[17-6] HIGH | Crash-reporting context (driver_id) bound 60+ lines after first
crash-capture call
File: driver-app/app/_layout.tsx:129,193
Finding: captureMessage('driver-app cold start') fires at line 129; setUser()
is not called until line 193. A crash during initializeAuth / font load /
location init reports anonymously — support cannot triage.
Fix: Move setUser(uid, {role: 'driver'}) immediately after initializeAuth
completes, before captureMessage. Effort: 1.5 h
Risk score: 16 (HIGH × self × likely)
Regulations: PIPEDA, SOC2
Owner: driver-app · Sprint: P1

[17-7] MEDIUM | Backend request_id not propagated to Stripe API calls
File: backend/routes/payments.py:40-95
Finding: stripe.Customer.create() and stripe.PaymentIntent.create() are called
without the backend request_id as idempotency_key or metadata. Stripe webhook
failures cannot be correlated to backend logs.
Fix: Extract request.state.request_id; pass as idempotency_key (or metadata)
in every Stripe create/update call. Effort: 1 h
Risk score: 12 (MEDIUM × self × possible)
Regulations: PCI-DSS, SOC2
Owner: backend · Sprint: P2

[17-8] LOW | WS heartbeat task cancellation not logged on disconnect
File: backend/routes/websocket.py:447-449
Finding: hb_task.cancel() fires silently. Connection-leak debugging is harder

Fix: Add logger.debug(f"Cancelled heartbeat for {connection_key}") after cancel.
Effort: 0.25 h
Risk score: 2 (LOW × self × rare)
Regulations: PIPEDA
Owner: backend · Sprint: P3

[17-9] RECOMMENDATION | Crashlytics SLO / dashboard link not documented;

Owner: driver-app + product · Sprint: P4

[17-10] MEDIUM | Liveness alerting: none of the 7 background loops emit

TASK 18 — DISASTER RECOVERY / BUSINESS CONTINUITY
================================================================================

[18-1] CRITICAL | Stripe outage blocks ride completion — no payment queue fallback
File: backend/routes/rides.py:1318-1595
Finding: complete_ride() calls stripe.PaymentIntent.create() inline. Any Stripe
5xx or network timeout fails the entire complete_ride request — driver cannot
end the trip, rider is stuck in `in_progress`. No deferred-charge queue, no
failover to wallet, no retry from background worker.
Fix: Move Stripe charge to async queue; on Stripe failure, mark ride
`payment_pending` and let payment_retry_loop handle settlement. Effort: 4 h
Risk score: 36 (CRITICAL × org × likely)
Regulations: PCI-DSS, SOC2, SK-TNC
Owner: backend · Sprint: P0

[18-2] HIGH | FCM dispatch has no SMS / in-app fallback chain
File: backend/routes/rides.py:358-374
Finding: Dispatch sends ride offer via FCM only. If FCM is degraded or token
is stale, driver never sees the offer. Match-rate KPI (≥85%) will collapse
during a Firebase incident. SK-TNC requires demonstrable dispatch
reliability for service-area approval.
Fix: Cascade — FCM → in-app WS push → SMS via Twilio if WS not connected
within 3 s. Track per-channel delivery in dispatch_attempts table.
Effort: 6 h
Risk score: 18 (HIGH × org × likely)
Regulations: SK-TNC, SGI
Owner: backend · Sprint: P1

[18-3] HIGH | Offline queue has no idempotency keys — double-charge risk
File: shared/api/offlineQueue.ts:130-170
Finding: When the driver app is offline and queues a tip-confirm or fare-end
mutation, replay on reconnect uses no Idempotency-Key header. If the mobile
device retries before the server confirms, the same tip can post twice.
Fix: Generate UUID v4 idempotency_key at enqueue time; pass as header on
replay; backend dedup on (key, user_id) tuple. Effort: 3 h
Risk score: 24 (HIGH × org × likely)
Regulations: PCI-DSS, SOC2
Owner: shared · Sprint: P1

[18-4] MEDIUM | AsyncStorage stale-state can override server truth on reconnect
File: driver-app/store/driverStore.ts:12-18
Finding: Hydration from AsyncStorage runs before backend re-fetch. If the
driver toggled offline on another device or the backend marked them
`document_expired`, the local store wins until the next refresh. No
warning banner; no force-reconcile.
Fix: Add `last_server_sync_at` field; if stale > 5 min, show banner
"Reconnecting…" and block go_online until reconcile. Effort: 2 h
Risk score: 6 (MEDIUM × team × likely)
Regulations: SK-TNC
Owner: driver-app · Sprint: P2

[18-5] MEDIUM | Redis presence read has no timeout
File: backend/services/dispatch_service.py:206-212
Finding: redis.get() in dispatch presence check uses default socket timeout.
Under load, a slow Redis can stall the entire dispatch loop. Single bad
node delays all offers.
Fix: Wrap with asyncio.wait_for(..., timeout=0.25); on timeout, treat
driver as offline and continue. Effort: 1 h
Risk score: 8 (MEDIUM × team × possible)
Regulations: SK-TNC
Owner: backend · Sprint: P2

[18-6] MEDIUM | WS reconnect has no UI feedback during back-off
File: driver-app/hooks/useDriverDashboard.ts:18
Finding: Reconnect logic uses exponential back-off but the UI shows
"Online" the entire time. Driver cannot tell they are missing offers
during a multi-second back-off window.
Fix: Surface a "Reconnecting…" banner from the WS state machine; gate
go_online button on connected state. Effort: 2 h
Risk score: 6 (MEDIUM × self × likely)
Regulations: SK-TNC
Owner: driver-app · Sprint: P2

[18-7] MEDIUM | Supabase circuit breaker has no fallback cache
File: backend/db_supabase.py:43-106
Finding: run_sync() retries once on H2 GOAWAY; on persistent failure it
raises DatabaseError. There is no read-through cache for hot lookups
(driver eligibility, fare config) — a brief Supabase outage takes the
entire app offline.
Fix: Add Redis read-through with 60 s TTL for: driver_status, vehicle
docs, fare_config. Reads only — never cache writes. Effort: 5 h
Risk score: 9 (MEDIUM × org × possible)
Regulations: SOC2
Owner: backend · Sprint: P2

[18-8] MEDIUM | Driver payout endpoint missing @idempotent_endpoint
File: backend/routes/drivers.py:1454-1466
Finding: POST /drivers/payouts/instant is not wrapped with the standard
idempotency decorator. A network retry can trigger a second Stripe
transfer. Manual reconciliation only catches it after the fact.
Fix: Apply @idempotent_endpoint(scope="payout"); require client-supplied
Idempotency-Key. Effort: 3 h
Risk score: 12 (MEDIUM × team × likely)
Regulations: PCI-DSS
Owner: backend · Sprint: P2

[18-9] LOW | Migrations have no rollback SQL files
File: backend/migrations/
Finding: 37 forward migrations exist, 0 down-migration files. CLAUDE.md
requires rollback plan in top comment, but no executable rollback path
exists. Forward-only is fine for additive schema changes; risky for

Fix: For migrations adding NOT NULL or FK constraints, ship a paired
rollback file under migrations/down/. Update migrate.py to support
--rollback flag. Effort: 8 h
Risk score: 4 (LOW × team × possible)
Regulations: SOC2
Owner: backend · Sprint: P3

[18-10] LOW | No documented RTO/RPO targets
File: docs/runbooks/ (missing)
Finding: SOC2 requires documented Recovery Time Objective and Recovery

Effort: 3 h
Risk score: 2 (LOW × self × rare)
Regulations: SOC2, PIPEDA

TASK 19 — FRAUD PREVENTION
================================================================================

[19-1] HIGH | Self-referral check uses stale PII — gameable with email aliases
File: backend/routes/drivers.py:2401-2440
Finding: Referral validation compares (referrer_phone, referee_phone) only.
A driver can self-refer using a Twilio test number or relative's SIM,
bypassing the check. No device-fingerprint, no IP-block, no PII similarity
check (same address, same bank, same documents).
Fix: Add device fingerprint (X-Device-ID); reject if (device, IP, bank
account, address) match referrer within 30 days. Effort: 3 h
Risk score: 18 (HIGH × org × likely)
Regulations: AML, PIPEDA
Owner: backend · Sprint: P1

[19-2] HIGH | No velocity limits on signup per device / IP
File: backend/routes/auth.py:136-198
Finding: signup endpoint rate-limited only by phone number (OTP). Same IP
or device can register N accounts with N phone numbers. No throttle on
{device_id, ip} tuple — fraud rings can mass-onboard.
Fix: Add SlowAPI key_func that hashes (device_id, ip); cap at 3 signups
per IP per 24 h. Audit-log denials. Effort: 4 h
Risk score: 18 (HIGH × org × likely)
Regulations: AML, PIPEDA
Owner: backend · Sprint: P1

[19-3] HIGH | Bank account update bypasses challenge (account-takeover risk)
File: backend/routes/drivers.py:1377-1405
