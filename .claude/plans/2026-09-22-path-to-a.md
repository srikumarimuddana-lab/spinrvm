# Path to an A — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reach the A bar in `docs/audit/2026-09-01-path-to-a-grade.md`: a two-city, ~500-driver quarter with no hand-run migration, no unexplained reconciler repair, every latency target paged from an alert, and a new engineer able to ship a money-path change inside a week.

**Architecture:** Finish `.claude/plans/2026-09-22-director-review-remediation.md` first (that plan tops out at B+). Then execute the already-written designs in `plans/2026-09-01-critical-topology-remediation-plan.md` — WS-D (flags) before WS-B (one transaction per hot write) — and only then the proof work this file adds (alerts, secrets, nightly load, packaging, the edge-case matrix). Do not invent a second flag system or a second transaction layer.

**Tech Stack:** Existing FastAPI, Fly, Redis, Supabase. New pieces named here: `backend/utils/flags.py`, `asyncpg` pool in `backend/repositories/_pg.py`, Redis `GEOADD`/`GEOSEARCH`, `import-linter`, `backend/pyproject.toml`, Grafana burn-rate alerts on the histograms that already exist. No Kafka, no Kubernetes, no microservice split.

**Spec:** `docs/audit/2026-09-01-path-to-a-grade.md` section 5 (the grep checklist and the quarter). Where this plan and ADR-014 disagree, the conflict is called out in A4 and is a decision, not a silent override.

## Global Constraints

- The B+ plan's exit criteria are true before A1 starts. In particular: Fly waits for green `backend-test`, `release_command` runs migrations, a worker process exists, money loops skip the tick when Redis is down, PostGIS is the live match provider, and `detail=str(e)` is zero under `backend/routes`.
- One logical change per commit, ≤3 files, ≤~200 lines, or split.
- Live surfaces get `docs/change-log/YYYY-MM-DD-<slug>.md`.
- Money stays `Decimal`. Insurance period rows are append-only.
- Every new user-visible behavior and every WS-B path ships behind `flag_enabled` (WS-D), default off, money flags `fail_mode="last_known_good"`.
- Supabase pooler is PgBouncer transaction mode. The asyncpg pool uses `statement_cache_size=0`. No prepared statements, no session `SET`, no advisory lock that outlives the transaction.
- Do not start settlement on the new pool (WS-B task B9) until ride-arrived, trip-start, location, and claim have been on in production for 14 days with zero `spinr_pg_*` breaker opens.
- A grade is not awarded on merge day. Correctness A and telemetry A include a 30-day clock.
