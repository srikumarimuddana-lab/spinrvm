[01-1] HIGH | UnboundLocalError on first-ever rating: average_rating only
defined inside `if rated_rides:` block but used unconditionally
File: backend/routes/rides.py:1788,1796,1801-1803
Finding: `average_rating = round(...)` is assigned only inside the
`if rated_rides:` branch (line 1796), but lines 1801-1803 reference it
unconditionally to build the update payload. When a driver receives their
first rating and no prior `rated_rides` exist, this raises
UnboundLocalError → 500 response → first-ever rating endpoint crashes.
Compounds 19-1 (rating field-name mismatch) — even after 19-1 fixes the
field, the FIRST rating against any driver still trips this path.
Fix: `average_rating = driver.get('rating', 5.0)` before the conditional;
update the local only when `rated_rides` is non-empty.
Effort: 1 h
Risk score: 24 (HIGH × org × likely)
Regulations: SK-CPPA
Owner: backend · Sprint: P0

[02-1] HIGH | Firebase ID token verified without `audience=` parameter
(DV-10 dup at HEAD)
File: backend/routes/auth.py:392,403,407,408
Finding: `_firebase_auth.verify_id_token(body.firebase_token)` is called
without an audience parameter. A subsequent manual aud-claim check is
gated on `if driver_app_id` — if `FIREBASE_DRIVER_APP_ID` is unset, the
audience check is skipped. Confirms DV-10 still open at HEAD. The same
issue exists for the rider audience (rider Phase E flagged this as 19-6,
21-1, 22-5).
Fix: Pass `audience=settings.FIREBASE_DRIVER_APP_ID` to verify_id_token;
fail startup if the env var is missing in production.
Effort: 2 h
Risk score: 24 (HIGH × org × possible) — duplicate_of: DV-10
Regulations: PIPEDA
Owner: backend · Sprint: P1

[03-1] HIGH | JWT_SECRET length not enforced — only known-weak placeholder
values are blocked
File: backend/core/config.py:84-99
Finding: `_guard_production_secrets` checks `JWT_SECRET` against a list
of placeholder strings (`your-strong-secret-key`, etc.) but does not
enforce a minimum length. A 4-character secret passes validation. HS256
uses the secret as the symmetric signing key — short secret = weak
signature. CLAUDE.md says "JWT_SECRET — must be ≥32 chars; startup fails
in production with weak value" but this isn't actually enforced.
Fix: After the placeholder check, add `if len(value) < 32: raise
ValueError("JWT_SECRET must be ≥32 chars in production")`.
Effort: 1 h
Risk score: 28 (HIGH × org × likely)
Regulations: PIPEDA, SOC2
Owner: backend · Sprint: P1

[04-1] MEDIUM | `float()` used for monetary amounts in corporate allowance
grant — CLAUDE.md "Decimal only" violation on a non-fare path
File: backend/routes/corporate_company.py:269,272
Finding: `amount=float(request["amount"])`, `floor=float(wallet.get(
"soft_negative_floor", -50))`. The pre-commit float-arithmetic hook
covers fare code; corporate wallet code is outside the hook's path.
Same family as 20-1 (rider Phase E flagged the rider wallet path) — this
is the corporate-wallet sibling.
Fix: Replace with `Decimal(str(...))`; sweep `corporate_*.py` for the same
pattern; add the corporate paths to the pre-commit hook scope.
Effort: 2 h
Risk score: 16 (MEDIUM × self × likely)
Regulations: CRA, PCI-DSS
Owner: backend · Sprint: P2
