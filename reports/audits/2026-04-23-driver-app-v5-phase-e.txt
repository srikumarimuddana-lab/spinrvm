TASK 17 — OBSERVABILITY

[17-1] HIGH | WS disconnect logs missing last-heartbeat timestamp + close code
File: backend/routes/websocket.py:439,544
Finding: WebSocket error handler logs a generic message without the close_code
or last-heartbeat timestamp. Dispatch-debugging requires both.
Fix: Emit structured disconnect event {connection_key, client_type,
last_heartbeat_ts, close_code}. Effort: 1.5 h
Risk score: 16 (HIGH × self × likely)
Regulations: PIPEDA
Owner: backend · Sprint: P1

[17-2] MEDIUM | Background location subscription has no error callback on
permission revocation
File: driver-app/hooks/useDriverDashboard.ts:320-377
Finding: Location.watchPositionAsync has no error handler. Backend is never
notified when the OS kills the background task or the driver revokes
permission — dispatch continues with stale GPS.
Fix: Add error callback emitting captureException + POST
/drivers/location-telemetry with stop reason. Effort: 2 h
Risk score: 12 (MEDIUM × org × possible)
Regulations: PIPEDA
Owner: driver-app · Sprint: P1

[17-3] MEDIUM | Crash reports omit driver_id and ride_id in extras
File: driver-app/store/driverStore.ts:408,507,521
Finding: recordNonFatal calls pass {store, action} only. Support triage is
ambiguous: cannot determine which ride or driver was affected.
Fix: Augment recordNonFatal with {driver_id, ride_id} from activeRide context.
Effort: 1 h
Risk score: 8 (MEDIUM × self × likely)
Regulations: PIPEDA
Owner: driver-app · Sprint: P2

[17-4] MEDIUM | Stripe API failures logged as .warning() instead of .error()
File: backend/routes/payments.py:169,191,256
Finding: Stripe API errors use logger.warning(), violating the CLAUDE.md rule
that critical-path DB/auth/payment errors must use .error(). Production log
aggregation typically drops warnings — Stripe failures silently missed.
Fix: Replace logger.warning with logger.error; include full exception.
Effort: 0.5 h
Risk score: 8 (MEDIUM × org × possible)
Regulations: PCI-DSS, SOC2
Owner: backend · Sprint: P1

[17-5] MEDIUM | document_expiry_loop has no success-path heartbeat
File: backend/utils/document_expiry.py:192-200
Finding: Loop logs only on exception, not on each successful iteration. 12 h
interval means a stuck loop can go 24+ h before detection. Related to DV-2
(doc-expiry wrapper bug) — if that fix lands but the loop silently stops,
nobody notices.
Fix: Emit logger.info("document_expiry_heartbeat",
extra={last_run_at, drivers_checked, drivers_suspended}) after each cycle.
Effort: 0.5 h
Risk score: 8 (MEDIUM × org × likely)
Regulations: SOC2
Owner: backend · Sprint: P2

[17-6] HIGH | Crash-reporting context (driver_id) bound 60+ lines after first
crash-capture call
File: driver-app/app/_layout.tsx:129,193
Finding: captureMessage('driver-app cold start') fires at line 129; setUser()
is not called until line 193. A crash during initializeAuth / font load /
location init reports anonymously — support cannot triage.
Fix: Move setUser(uid, {role: 'driver'}) immediately after initializeAuth
completes, before captureMessage. Effort: 1.5 h
Risk score: 16 (HIGH × self × likely)
Regulations: PIPEDA, SOC2
Owner: driver-app · Sprint: P1

[17-7] MEDIUM | Backend request_id not propagated to Stripe API calls
File: backend/routes/payments.py:40-95
Finding: stripe.Customer.create() and stripe.PaymentIntent.create() are called
without the backend request_id as idempotency_key or metadata. Stripe webhook
failures cannot be correlated to backend logs.
Fix: Extract request.state.request_id; pass as idempotency_key (or metadata)
in every Stripe create/update call. Effort: 1 h
Risk score: 12 (MEDIUM × self × possible)
Regulations: PCI-DSS, SOC2
Owner: backend · Sprint: P2

[17-8] LOW | WS heartbeat task cancellation not logged on disconnect
File: backend/routes/websocket.py:447-449
Finding: hb_task.cancel() fires silently. Connection-leak debugging is harder
without explicit lifecycle logging.
Fix: Add logger.debug(f"Cancelled heartbeat for {connection_key}") after cancel.
Effort: 0.25 h
Risk score: 2 (LOW × self × rare)
Regulations: PIPEDA
Owner: backend · Sprint: P3

[17-9] RECOMMENDATION | Crashlytics SLO / dashboard link not documented;
no pre-launch crash-free gate
File: shared/services/errorReporting.ts:1-17
Finding: Header comment notes Crashlytics → Sentry upgrade path (SPR-04) but
there's no documented SLO (crash-free > 99.5%) or dashboard URL. Phase E
kickoff requires crash-free rate > 99.5% for 14 days before launch.
Fix: Add dashboard URL + SLO to pre-launch checklist. Effort: 0.5 h
Risk score: 2 (RECOMMENDATION × self × possible)
Regulations: SOC2
Owner: driver-app + product · Sprint: P4

[17-10] MEDIUM | Liveness alerting: none of the 7 background loops emit
last_run_at metric
File: backend/core/lifespan.py (all 7 loops)
Finding: Dimension D17 requires per-loop liveness metrics so SRE alerts fire
if any loop stops (2× interval). None of the 7 loops emit this metric.
Fix: Emit last_run_at metric + log per iteration; add SRE alert rule:
time_since(last_run_at) > 2× interval_seconds. Effort: 2.5 h
Risk score: 8 (MEDIUM × org × likely)
Regulations: SOC2
Owner: backend + devops · Sprint: P2

[17-11] PASS | Firebase Crashlytics integrated; bundle ID correct
File: driver-app/app.config.ts:4,34
Evidence: bundleIdentifier = com.spinr.driver; googleServicesFile =
./GoogleService-Info.plist; Firebase plugins included (lines 185-186).

[17-12] PASS | PrivacyInfo.xcprivacy declares location + Crashlytics API reasons
File: driver-app/app.config.ts:44-126
Evidence: NSPrivacyAccessedAPITypes for Crashlytics (C617.1, 35F9.1); CrashData
+ preciseLocation declared in NSPrivacyCollectedDataTypes.

[17-13] PASS | Request-ID middleware propagates correlation ID
File: backend/core/middleware.py:110-119
Evidence: RequestIDMiddleware generates/reads X-Request-ID, binds via
logger.contextualize(), echoes in response header.
