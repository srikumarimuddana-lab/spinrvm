# Roadmap — Now / Next / Later

**Lane:** R20 Synthesizer · **Wave:** W5 · **Date:** 2026-09-25 · **Mode:** report-only; nothing here has been implemented. Supersedes `rapid-baseline-2026-09-24/ROADMAP.md` (its N1–N11, X1–X13 and L1–L7 are folded in below; the mapping is in §7).

## §0 How to read this

- **Horizons.** **Now** = start within 14 days; mostly zero-code, config or human actions, plus a few small, high-value code fixes. **Next** = the following 2–6 weeks. **Later** = after live testing stabilises, or when a dependency lands. Nothing here is a rewrite; `04-blueprint.md` marks rewrite-only ideas and they are not scheduled.
- **Every item** cites the finding ids it closes and the `matrices/risk-register.md` row, names an **owner role** (legend in the register; most roles have no named person yet — `matrices/ownership.md`), a **flag or switch** (or "none" with the reason), a **rollback** that does not rely on `git revert` for anything already applied to live data, and its **dependencies**.
- **Human-only** marks an item no agent can do (console access, a legal or tax answer, a budget decision). These are the items that historically stall (`06-operating-model.md` §4.1), so each has a named decision in `05-escalations.md`.
- **Lane** is the set of files an item touches. **Items in different lanes touch disjoint files and can run in parallel.** Items in the same lane must be sequenced. Two special lanes: **DB** (any new migration — numbering collisions mean migrations are serialised through one owner) and **HUMAN** (no repo files).
- **Mobile flags and rollback.** There is no client-side flag SDK; mobile flags reach the device as a field in a backend response (the `rideless_sos_enabled` pattern). Each mobile item must name that field and say what older binaries do. "Flag off" works only for server-delivered flags; a JS change is rolled back by an **OTA republish of the previous bundle, effective on each device's next launch** — not instantly (08-hostile-review §1.3).
- **Verification** follows CLAUDE.md: any rider-app or driver-app change has no visual tooling, so UI items must say "reasoned about, not screenshotted" and get a manual device pass; admin pages with a seeded visual baseline will need a human to re-capture it after an intended change.

**Lane key:** `HUMAN` (no files) · `OPS` (provider consoles and secrets only) · `INFRA-CFG` (`backend/fly.toml`, `railway.json`, `render.yaml`) · `CI` (`.github/workflows/*`, `.gitleaks.toml`, `.semgrep/*`) · `AGENT-CFG` (`.claude/settings.json`, `.claude/agents/*`, `.claude/hooks/*`) · `DOCS` (`docs/**`, `CLAUDE.md` with owner approval, `.claude/context/*`) · `AUTH` (`backend/sms_service.py`, `routes/auth.py`, `routes/users.py`, `dependencies/`, `utils/crypto.py`, `utils/refresh_tokens.py`) · `MONEY` (`features.py` fare functions, `routes/drivers/earnings.py`, `utils/referral_payout.py`, `services/fare_service.py`, `services/payment_service.py`, `routes/webhooks.py`, `utils/reconciliation.py`, `utils/t4a_pdf.py`, receipt renderers) · `CORP` (`services/corporate_wallet_*`, `repositories/corporate_repo.py`, `routes/corporate_*`) · `DISP` (`routes/rides/matching.py`, `services/dispatch_service.py`, `repositories/driver_repo.py`, `routes/drivers/status.py`, `routes/drivers/ride_flow.py`, `services/driver_availability_service.py`) · `OBS` (`utils/loop_monitor.py`, `utils/loop_alert.py`, `utils/t4a_annual_job.py` heartbeat, `tests/test_loguru_call_conventions.py`, metric emit sites named per item) · `ADMIN` (`routes/admin/*`, `admin-dashboard/**`) · `SAFETY` (`routes/rides/safety.py`, `utils/safety_paging.py`, `services/zoho_desk_integration.py`) · `RIDER` (`rider-app/**`) · `DRIVER` (`driver-app/**`) · `SHARED` (`shared/**`) · `DB` (`backend/migrations/**`).
