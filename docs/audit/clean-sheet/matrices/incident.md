## §0 Method

- **Scope, per the task**: `docs/incidents/` (3 files, all read in full this session), `docs/change-log/`
  incident notes (searched by filename for `incident`/`P0`/`P1`, plus a targeted read of the two
  change-log entries that document the same root-cause chain as a `docs/incidents/` file — B42's
  webhook-loss fix and the A43 admin-bypass evidence that explains how B42's PR merged unreviewed),
  and `docs/audit/breach-record.md` (read in full this session, Incident 1).
- **What was excluded as not a production/security incident**: several `docs/change-log/` filenames
  matched a broad `incident`/`P0`/`P1` grep only because they touch the `safety_incidents` *feature*
  (admin UI for safety-incident records, e.g. the 2026-08-21/08-31 admin-dashboard batches) or use
  the words "P0"/"P1" in an unrelated sentence — spot-checked and excluded, not incidents themselves.
- **Root cause family** maps each incident to `00-history.md`'s HIST-001..017 recurrence families
  (cited, not re-derived) where a clean fit exists; where none of the 17 families fits, this file
  says so rather than forcing a match.
- **Detection path** distinguishes an automated alert/monitor firing vs. a human noticing (via a
  CI-gate check, a user report, or a manual investigation) — this file finds this matters enough to
  call out as its own pattern in §2.
- Evidence labels: VERIFIED (this session's own direct read of the cited file) / cited-VERIFIED
  (another lane's direct read this audit).

## §2 Cross-incident pattern

**Zero of the four incidents in this table were detected by an automated alert.** Every one was
found by a human: verifying a CI gate by hand (#1), a filed GitHub issue (#2), a live investigation
session re-examining a narrower report (#3), and a user-facing PR report backed by a Sentry issue
that itself never paged anyone (#4). This is consistent with `matrices/risk-register.md` RR-86
(cited): "MTTD/MTTR for loop, Redis and deploy failures is therefore unknown" — the same single-
webhook alerting gap that leaves the 44 background loops unmonitored also describes why none of
these four incidents had a working automated trip-wire. Three of the four (#1, #2, #3) also show
the same secondary pattern: **the detection tool that should have caught it was itself silently
broken or narrowly scoped** — a gitleaks config that loaded zero rules (#1), a keyword-matched
secret-scan rule that didn't cover the second file's column shape (#2), and a webhook handler whose
failure produced no error a human would ever see, by design of the retry-dedup logic (#3).
