## 1. Issue / gap identified

Epic #2785 named this repo's complete absence of visual-regression tooling as a Phase 1 prerequisite (also independently stated as a standing gap in `CLAUDE.md`). 27 existing Playwright e2e specs in `admin-dashboard` use zero `toHaveScreenshot()` calls.

## 2. Root cause

Never built. Not a regression — a capability gap.

## 3. Fix / remediation

- Added `admin-dashboard/e2e/visual-regression.spec.ts`: full-page `toHaveScreenshot()` snapshots for 6 pages — `/login` (pre-auth chrome), `/dashboard` (home), `/dashboard/rides`, `/dashboard/drivers`, `/dashboard/monitoring`, `/dashboard/settings`. A deliberately tight starter set (not all 41 routes), chosen to exercise the shared sidebar/topbar/card/table/button primitives across diverse page shapes (stat-card dashboard, data tables, a form-heavy settings page, pre-auth chrome) without the cost of screenshotting every route on every run.
- Added a `visual-regression` Playwright project in `playwright.config.ts`, kept structurally separate from the existing `chromium` project (`testIgnore` on `chromium`, own `testMatch` on the new project) — run only via explicit `--project=visual-regression`, never picked up by a bare `playwright test`/`npm run test:e2e` invocation.
- Added `expect.toHaveScreenshot: { maxDiffPixelRatio: 0.01 }` globally — a small tolerance for anti-aliasing jitter between runs on the same CI runner.
- Added a new CI job `visual-regression-test` in `ci.yml`, `continue-on-error: true` (unconditionally, for now — see §8), separate from the existing `e2e-test` job. Also changed `e2e-test`'s run command from the implicit `npm run test:e2e` (bare `playwright test`, runs all projects) to explicit `npx playwright test --project=setup --project=chromium`, so it can never accidentally pick up the new project regardless of future project additions.
- Added `.github/workflows/update-visual-baselines.yml`: a `workflow_dispatch`-only workflow that builds, starts the server, runs the visual spec with `--update-snapshots`, and uploads the resulting PNGs as a downloadable artifact — deliberately does **not** auto-commit (see §8).
- **Did not commit any baseline PNGs in this change** — see §8 for why, and follow-up issue #2809 for the concrete next step.

## 8. Rollback plan

`git-revert-safe` — pure CI/test-infrastructure additions, no data/migration/Stripe state, and the new job is already non-blocking.

**Why no baseline PNGs are committed here, deliberately**: verified locally (this sandbox's pre-installed Chromium is revision 1194; the repo's pinned `@playwright/test` expects 1217, confirmed via the exact error `browserType.launch: Executable doesn't exist at .../chromium_headless_shell-1217/...`) that this environment cannot produce a baseline matching what CI's `npx playwright install --with-deps chromium` step would actually render. Committing a baseline generated here would very likely fail the very first real CI comparison — a self-inflicted false-positive-red gate, the same failure mode already flagged elsewhere this session (`review`/#2503: a gate nobody trusts is worse than no gate). The `update-visual-baselines.yml` workflow exists specifically so baselines come from CI's own renderer instead; running it once is tracked as follow-up #2809, explicitly non-urgent since the gate is non-blocking either way.
