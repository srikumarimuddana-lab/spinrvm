Design Notes
Booking Friction Analysis context
  • Rider cancel rate target ≤ 8% — friction before confirm is the leak
  • Every extra tap = ~12% drop-off (industry research)
  • Common trips (home/work) = 60–70% of all rides for weekly users
  • First-time users need map orientation; regulars need speed
A — Map-First familiar
  • Lowest learning curve — matches Uber/Lyft muscle memory
  • Bottom sheet is discoverable but adds 1 extra tap
  • Driver dots give supply context before searching
  • Risk: sheet height competes with map — users may miss saved places
B — Search-First efficient
  • Large search bar is immediately actionable — clearest affordance
  • Shortcuts grid makes common trips 1-tap from home screen
  • Map is auxiliary — reduces spatial disorientation risk
  • Risk: newcomers may miss map context; feels functional not warm
C — Smart-Predictive ★ recommended
  • Context card ("Heading to Work?") is 1 tap → route preview
  • Prediction handles 60–70% of trips with zero typing
  • Search still available for new destinations
  • Supply indicator reduces anxiety ("are there cars nearby?")
  • Fare shown in saved place tiles → no surprise at confirm
Recommendation
Variant C wins on speed for habitual users — the most valuable segment. The context card removes the biggest friction: thinking about where you're going. For first-time users, the search and map are still present but not forced. The fare transparency in route preview (full line-item breakdown) is unique to Spinr and must be present before every booking.
